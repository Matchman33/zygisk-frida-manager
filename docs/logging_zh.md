# 日志清空与脚本控制台说明

更新日期：2026-09-23

## 原问题

旧版清空按钮只执行 `logText.setText("")`，重新进入页面会启动不带读取边界的 logcat，因此历史记录重新出现。旧加载器只把自己的诊断写入 `ZFM`，没有转发用户的控制台输出；默认标签又只有 `ZygiskFrida`。

[Frida 官方文档](https://frida.re/docs/gadget/#script)说明自主脚本的控制台输出走标准输出或标准错误；[控制台 API](https://frida.re/docs/javascript-api/#console)也说明具体输出位置依赖宿主。因此，读到模块日志不代表能读到用户脚本的 console。

## 新的清空语义

- 垃圾桶清空管理器日志并持久保存清空时间，之后仅显示新的记录。
- 清空时间应用于所有标签，切页、切换标签、停止再开始或重启管理器不会恢复清空前的记录。
- 同一视图恢复时从最后已显示的微秒时间续接，按边界记录出现次数去重，保留同时间戳的新消息。
- 清空不执行系统级 `logcat -c`，其他应用和外部调试工具的系统日志保留。
- 屏幕最多保留约六万四千字符，生产端缓冲最多约三万二千字符，界面按批次刷新。

## 控制台输出

日志标签的用途：

| 标签 | 用途 |
|---|---|
| Frida | Gadget 本身的启动、端口监听、连接和运行错误，适合排查 Gadget 为什么没有正常启动 |
| ZygiskFrida | 模块识别目标、注入延时和加载库的过程 |
| ZFM (loader) | 管理器生成的加载器读取、解密和加载脚本的诊断 |
| 脚本 console | 用户脚本的控制台输出，对应 ZFM-Script |
| 全部关键标签 | 同时查看以上四类，适合观察完整流程 |

`Frida` 不是专门收集用户脚本 `console.log` 的标签；脚本控制台的自动转发使用独立标签。

重新导入普通脚本或子配置后，生成的新加载器将 `console.log`、`info`、`warn`、`error` 和 `debug` 写入 `ZFM-Script`。在管理器选择「脚本 console」或默认「全部关键标签」即可查看。保留原控制台调用，不依赖 Java 桥，不生成 Toast。

多个参数按空格连接，对象尽可能转成 JSON，异常保留堆栈。多行消息逐行输出，长消息按较小片段写入，避免单条 Android 日志长度限制截断正文。每条带脚本名，logcat 同时保留进程和线程信息。

适用范围：管理器生成的普通明文、本地解密及设备内解密加载器。旧版设备文件不会因安装新 APK 自动更新，需要重新选择并推送原脚本，或重新导入原子配置。仅推送目标配置不会更新已有加载器。

Frida 客户端另行注入的脚本、单独的 Worker 上下文和 frida-compile 原生模块包不自动接入。明文模块包继续走 Gadget 原生加载；模块包不支持设备内解密加载器，会在导入时提示。脚本主动覆盖 console 方法也可能绕过转发。
