# ZygiskFrida 管理器使用手册

文档版本：2026-09-23
适用应用：`re.zyg.fri.manager` 1.1.0

本手册面向直接使用管理器的用户，按实际操作流程说明如何选择目标、配置注入、推送脚本、查看日志和排查问题。构建入口见 [管理器 README](../README.md)，实现原理和历史真机记录见 [开发说明](implementation_zh.md)。模块和 Gadget 的来源见 [外部依赖说明](upstream_zh.md)。

> 仅在你拥有或已获得明确授权的设备和应用上使用本工具。

## 1. 使用前准备

本节条件适用于 ZygiskFrida 模块注入。仅使用「工具 → Patch SO」不需要 Root 或模块，可直接按 [Patch SO 使用说明](patch_so_zh.md) 生成 SO、Gadget 和配置补丁包。

开始前确认以下条件：

1. Android 设备已取得 root 权限。
2. 已安装并启用 Magisk、KernelSU、KernelSU Next 或 APatch 中的一种 root 管理器。
3. 已具备可用的 Zygisk 环境。需要独立实现时，可从 [Zygisk Next 官方 Releases](https://github.com/LSPosed/ZygiskNext/releases) 下载模块，按上游说明安装并重启。
4. 已刷入 ZygiskFrida 模块并重启设备。
5. 已安装 ZygiskFrida 管理器 APK。
6. 已在 root 管理器中向 `ZygiskFrida 管理器` 授予超级用户权限。

从仓库构建出 Debug APK 后，可在仓库根目录执行：

```shell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

也可以把 APK 发送到手机后，通过系统安装器完成安装。安装完成后，应先在 root 管理器中授权，再打开管理器进行环境检查。

管理器默认使用以下模块目录：

```text
/data/local/tmp/re.zyg.fri
```

其中常用文件为：

| 路径 | 用途 |
|---|---|
| `config.json` | 注入目标配置 |
| `libgadget.so` | 64 位 gadget |
| `libgadget32.so` | 32 位 gadget |
| `libgadget.config.so` | 默认 gadget 配置 |
| `scripts/` | 管理器推送的脚本、密文和 loader |

## 2. 首次启动检查

打开管理器后，使用底部菜单切换四个页面：

| 页面 | 内容 |
|---|---|
| 目标 | 设备状态、应用列表、添加与编辑目标、推送并应用 |
| 脚本 | Gadget 交互模式、脚本处理、表单与原始 JSON、保存和写入设备 |
| 日志 | 实时日志、标签筛选、开始或停止、清空和复制 |
| 工具 | 环境检查、模块目录、文件与子配置导入、加解密、命令输出 |

切换分页会保留当前进程中的表单草稿、滚动位置和工具输出；退出应用或系统回收后，持久设置仍以已保存的内容为准。从分页按系统返回键会回到「目标」，在「目标」再返回会退出前台。选择应用、编辑目标属于详情页，顶部返回箭头会回到上一页。

「目标」页顶部显示环境摘要和通过的检测数量，点旁边的问号查看 Root、模块、Gadget 和配置的详细状态。诊断报告中的原始字段含义如下：

| 状态 | 含义 | 正常值 |
|---|---|---|
| `ROOT` | 管理器能否执行 root 命令 | `ok` |
| `MODDIR` | 模块目录是否存在 | `ok` |
| `GADGET` | 默认 gadget 是否存在 | `ok` |
| `CONFIG` | 设备上是否已有 `config.json` | `ok` 或首次使用时 `missing` |

首次使用时 `CONFIG=missing` 是正常现象，第一次执行「推送并应用」后会创建该文件。

如果 `ROOT`、`MODDIR` 或 `GADGET` 显示异常：

1. 点底部「工具」，或点「目标」页顶部状态区域。
2. 先点「测试 Root」。
3. 再点「环境自检」。
4. 根据下方输出检查 root 授权、模块状态和实际模块目录。

## 3. 最快上手：自动加载脚本

以下流程适合让 gadget 在目标应用启动时自动加载一个 `.js` 脚本，不需要电脑端 Frida 客户端持续连接。

### 第一步：添加目标

1. 在「目标」页点「注入目标」右侧的加号。
2. 搜索应用名称或包名。
3. 点选目标应用。
4. 如果目标不在已安装列表中，可打开选择页右上角菜单，使用「从 APK 文件选择…」。

从 APK 文件选择后，管理器可以通过 root 调用 `pm install -r -d` 安装 APK，然后将其设为目标。

### 第二步：配置目标

进入「编辑目标」后：

1. 保持「启用此目标」开关开启。
2. 设置注入延时，单位是秒。
3. 确认「注入的库」中包含与目标架构匹配的 gadget。
4. 点「Gadget / 脚本配置」。
5. 将交互模式选为「自动加载脚本」。
6. 选择脚本处理方式。
7. 返回目标编辑页，点「选择脚本并推送」。
8. 选择手机上的脚本文件。
9. 点「保存并推送」。

管理器会将脚本或密文写入模块目录，生成 gadget 配置，并把目标写入 `config.json`。

### 第三步：启动并检查

1. 回到主界面。
2. 长按目标，选择「强行停止并重启」；也可以手动重新启动目标应用。
3. 点底部「日志」。
4. 点标签按钮，在菜单中选择「全部关键标签」。

正常情况下会依次看到：

```text
ZygiskFrida: App detected
ZygiskFrida: Process init completed
ZygiskFrida: Injecting ...
Frida: gadget 启动或脚本加载信息
ZFM: loader 的解密、加载和完成信息
```

## 4. 主界面操作

### 添加目标

「注入目标」右侧的加号用于从已安装应用或 APK 文件中选择新的目标。添加后会立即进入目标编辑页；长按图标可查看名称。

每个目标会分别显示三类信息：

- `启用 / 停用`：本机保存的注入开关。
- `已推送 / 待推送`：当前本机配置是否与最近一次成功推送的内容一致；它不代表设备文件未被其他工具修改。
- `正在运行 · PID / 当前未运行 / 运行状态不可用`：管理器实时读取的目标进程状态。

### 推送并应用

「推送并应用」会把管理器本机保存的全部目标写入：

```text
/data/local/tmp/re.zyg.fri/config.json
```

推送前会显示目标数量、启用状态、延时和 gadget 配置路径。

注意：

- 推送是以管理器本机列表为准写入设备。
- 推送会先把 Gadget 副本、各脚本配置和 `config.json` 全部写到暂存目录，校验完成后再统一提交；提交失败会尝试恢复原文件。
- 推送过程中如果本机配置又发生变化，本次提交会取消，避免把混合版本标记为已推送。
- 如果设备上有本机列表中不存在的目标，确认窗口会警告这些目标将被删除。
- 遇到这种情况，应先用菜单中的「从设备导入」将配置合并到本机。
- 当本机没有任何目标时继续推送，会把设备配置写成空列表，从而停止全部目标注入。

### 长按目标

长按主界面中的目标可执行：

| 操作 | 说明 |
|---|---|
| 编辑 | 打开完整目标配置 |
| 启用 / 停用 | 修改本机状态，之后仍需推送才会写入设备 |
| 启动应用 | 直接打开目标应用 |
| 强行停止并重启 | 通过 root 停止目标后重新启动 |
| 导出子配置 | 将目标、密文和受控设置打包为 `.zfmcfg` |
| 删除 | 从本机列表删除，之后仍需「推送并应用」才能从设备配置移除 |

## 5. 编辑注入目标

### 目标进程

包名仅用于展示和复制，不能手动编辑。通过右侧「选择」按钮更换应用。

主进程通常等于应用包名，例如：

```text
com.example.app
```

Android 子进程通常带冒号，例如：

```text
com.example.app:remote
```

已有配置中的子进程名会保留；需要新增子进程目标时，可通过设备配置导入完整进程名。

### 注入延时

延时单位为秒，实际写入配置时会转换为 `start_up_delay_ms`。

计时起点是目标进程初始化完成之后，不是点击应用图标的时刻。模块会在注入前最后 10 秒输出倒计时日志。

建议先使用较短延时确认链路能够工作；如果目标在启动阶段发生冲突，再逐步增加延时。

### 注入的库

库会按界面中的顺序依次加载：

- 「64 位 Gadget」添加默认 64 位 `libgadget.so`。
- 「32 位 Gadget」添加 `libgadget32.so`。
- 「自定义库」添加其他绝对路径下的 `.so`。
- 每一项右侧的删除按钮可移除该库。

目标应用的位数必须与注入库架构匹配。64 位应用使用 64 位 gadget，32 位应用使用 32 位 gadget。

### Gadget 与脚本

「Gadget / 脚本配置」用于设置交互模式、监听地址、端口、脚本路径和脚本处理方式。

「选择脚本并推送」会根据当前脚本处理方式执行加密、解密、推送和 loader 生成，并自动把 gadget 配置接到最终脚本路径。

### 子进程 gating

这是实验性功能，支持三种模式：

| 模式 | 行为 |
|---|---|
| `freeze` | 子进程停留在 fork 返回前，不继续执行 |
| `kill` | 子进程创建后立即终止 |
| `inject` | 向子进程注入指定库后继续运行 |

使用 `inject` 时，子进程 gadget 必须是一个实际复制出来的独立文件，不能复用父进程同一个文件，也不能只创建符号链接。子进程 gadget 还应使用不同端口或启用 `pick-next`。

子进程 gating 可能影响应用退出和重启。出现残留进程时可执行：

```shell
adb shell 'su -c kill -9 $(pidof com.example.app)'
```

## 6. Gadget 交互模式

底部「脚本」页提供「表单」和「原始 JSON」两个编辑视图：

- **表单**：只显示当前交互模式需要的字段，保存或立即写入时直接使用当前表单，无需先手动生成 JSON。
- **原始 JSON**：用于高级配置。切换进入时会带入表单内容；返回表单会校验并反填。无效 JSON 或表单不支持的交互模式会保留在 JSON 视图。
- 在同一种交互模式下修改表单，会保留 `token`、`parameters` 等高级字段和顶层设置。切换交互模式会替换原有 interaction 内容，同时保留顶层设置。
- 「保存」只保存本机配置；「立即写入设备」会保存 Gadget 配置、启用写入，并执行推送流程。底部「脚本」页保存后停留本页，从目标编辑页进入时保存后返回目标。

脚本处理方式和可编辑密钥只作为页面草稿保留，点击保存后才写入本机配置。已有脚本更改处理方式或密钥时，必须重新选择源脚本，让管理器同步生成新的密文或 loader；只改设置不会再留下“界面是新参数、设备文件仍是旧参数”的状态。子配置锁定的密钥不会显示输入框；页面显示简短的锁定状态，旁边的问号可查看完整原因、脚本处理计划和配置文件路径。

每页顶部问号提供本页操作说明。交互设置、脚本处理、注入延时、注入库和子进程标题旁的问号提供对应项目的说明，主界面不会常驻大段提示文字。

### listen：等待客户端连接

适合手动连接 gadget、临时加载脚本或调试交互。

常用设置：

```text
地址: 127.0.0.1
端口: 27042
端口占用时: pick-next
```

如果启用 `on_load=wait`，Gadget 的加载流程会等待客户端连接。模块在后台线程延时注入，不保证应用主线程或界面暂停。
非零延时下，需等延时结束并出现 `Listening on ...` 日志后再连接。

连接 Gadget 时，先使用 `frida-ps -H 地址:端口` 枚举当前进程，再使用同一地址下的 `-n Gadget` 或刚枚举的 PID。
`Unable to act on other processes when embedded` 表示请求的 PID 与当前连接的 Gadget 宿主不一致；应用重启后不要复用旧 PID，多个 Gadget 运行时需核对端口。

连接示例：

```shell
adb forward tcp:27042 tcp:27042
frida -H 127.0.0.1:27042 -n Gadget
```

`listen` 模式要求目标应用拥有 Android `INTERNET` 权限，否则日志可能出现：

```text
Unable to create socket: Operation not permitted
```

### script：自动加载脚本

目标启动后直接加载设备上的脚本，无需 Frida 客户端。该模式不会打开监听端口，因此适合没有 `INTERNET` 权限的目标。

管理器切换到 `script` 模式时会移除 `on_load=wait`，避免应用在没有客户端连接的情况下永久暂停。

### connect：主动连接远端

gadget 会主动连接指定地址和端口。只有在已经准备好远端 Frida 控制端，并且设备可以访问该地址时才使用此模式。

## 7. 脚本处理方式

管理器提供四种脚本处理方式：

| 方式 | 输入文件 | 设备上保存 | 适用场景 |
|---|---|---|---|
| 明文直接推送 | 明文 `.js` | 明文脚本 | 调试方便，内容可直接查看 |
| 密文在设备内解密 | 已加密文件 | 密文 + loader | 明文只在目标进程内存中出现 |
| 密文解密后推送明文 | 已加密文件 | 明文脚本 | 需要在设备上直接查看脚本 |
| 明文加密后推送密文 | 明文 `.js` | 密文 + loader | 由管理器生成兼容密文 |

加密方式为 XOR + Base64，密钥必须是 ASCII。管理器会在推送前执行加解密回环检查，校验失败时不会继续写入设备。

### 脚本提示与日志

管理器不再生成或显示注入 Toast。需要 Toast 时，请在自己的脚本中实现；管理器会保留脚本原有的提示代码。

普通明文脚本会附加控制台日志加载器，脚本源码保持不变。设备内解密继续使用解密加载器。加载诊断写入「ZFM (loader)」，用户脚本的 console.log/info/warn/error/debug 写入「脚本 console」。

升级 APK 不会自动改写设备上以前生成的 loader。要移除旧 loader 中的自动提示，请重新选择并推送原脚本；来自子配置的目标可重新导入原 `.zfmcfg` 文件。仅「推送并应用」目标配置不会重新生成 loader。

## 8. 保存、推送与设备导入

目标编辑页有两个保存按钮：

| 按钮 | 行为 |
|---|---|
| 保存 | 只保存到管理器本机列表 |
| 保存并推送 | 保存后立即写入设备配置 |

主界面菜单中的「从设备导入」会读取设备上的 `config.json`，并提供：

- 「合并到本机」：保留本机目标，同时加入或更新设备目标。
- 「替换本机」：清空本机目标后完全采用设备配置。

在更换管理器 APK、清除应用数据或从手工配置迁移前，建议先确认设备上的 `config.json` 是最新版本。重新安装管理器后，可以通过「从设备导入」恢复目标列表。

## 9. 子配置的导出与导入

子配置文件扩展名为：

```text
.zfmcfg
```

它可以把一个目标需要的密文、gadget 配置和目标设置打包交给其他设备使用。

### 导出

导出前，脚本处理方式必须是以下之一：

- 「明文加密后推送密文」
- 「密文在设备内解密」

然后：

1. 长按主界面目标。
2. 选择「导出子配置」。
3. 决定是否允许接收方修改注入延时。
4. 决定是否允许接收方启用或停用目标。
5. 选择保存位置。

目标应用、注入库、脚本、加密方式、Gadget 配置和子进程设置会保持锁定。密钥会密封在文件中，不会在接收方界面显示。

### 导入

1. 点底部「工具」。
2. 点「导入子配置」。
3. 选择 `.zfmcfg` 文件。
4. 等待密文、loader、gadget 配置和 `config.json` 写入完成。

文件签名校验失败、锁定字段被修改或密钥无法解封时，管理器会拒绝导入。

子配置的密钥隐藏与签名主要用于防止随手查看和误修改，不等同于不可逆向的密码学保护。

## 10. 日志查看

底部「日志」页面首次进入时自动启动日志流。点顶部标签按钮可直接选择：

| 标签 | 主要内容 |
|---|---|
| `ZygiskFrida` | 模块识别目标、延时、注入库和错误信息 |
| `ZFM (loader)` | loader 解密、脚本加载和错误信息 |
| `Frida` | gadget 启动、监听端口和 Frida 错误 |
| `全部关键标签` | 同时显示以上三类 |
| `全部` | 完整 logcat，输出量较大 |

默认选择「全部关键标签」，其中包含「脚本 console」（ZFM-Script）。右侧垃圾桶清空管理器日志并保存清空时间；切页、切换标签、停止再开始或重启，都不会恢复清空之前的记录。此操作不删除其他应用的系统日志。

离开页面会暂停采集，返回时从上次显示的位置续接并去重；手动停止后切页仍保持停止。旧版已部署脚本需要重新导入原脚本或子配置，才能生成带控制台转发的加载器。客户端另行注入的脚本、单独 Worker 和 Frida 原生模块包不自动接入。详见 [日志说明](logging_zh.md)。

排查时建议先选择「全部关键标签」，重启目标后从进程启动阶段开始观察。

## 11. 工具与环境

底部「工具」页按环境、文件、加解密和诊断分组，包含：

模块目录、su 调用方式和自定义命令收在页面下方的「高级设置」中，点击展开后操作。

| 功能 | 用途 |
|---|---|
| Patch SO | 离线为指定 SO 添加 Gadget 依赖，使用预设或自定义配置导出 ZIP |
| 模块目录 | 修改模块文件所在目录 |
| su 调用方式 | 在自动、`su -c`、`su 0 sh -c` 之间切换 |
| 测试 Root | 执行 root 身份检查 |
| 环境自检 | 检查 root 管理器、模块目录、配置和 gadget 架构 |
| 查看 config | 读取设备上的 `config.json` |
| 目录列表 | 查看模块目录中的实际文件 |
| 导入 gadget | 将自定义 gadget 推送到模块目录并可设为当前 gadget |
| 导入脚本 | 将脚本文件放入模块脚本目录 |
| 加密脚本 / 解密脚本 | 在手机本地转换脚本并另存文件 |
| 自定义命令 | 以 root 身份执行输入的 shell 命令 |

「自定义命令」会直接以 root 身份执行内容。执行前应确认命令和路径，避免修改系统或删除错误文件。

运行检查后，下方「输出」区域自动展开。点「输出」可折叠或展开，垃圾桶图标清空输出；切换底部分页不会清空这些内容。

## 12. 常见问题

### ROOT=fail 或找不到 su

先到 Magisk、KernelSU 或 APatch 的超级用户页面，手动允许 `re.zyg.fri.manager`。KernelSU Next 可能会对尚未授权的应用隐藏 `su`，此时仅重试没有作用，必须先授权。

如果已经授权，进入「工具与环境」切换 `su` 调用方式后再次测试。

### MODDIR=missing

可能原因：

- ZygiskFrida 模块没有安装。
- 模块安装后尚未重启。
- 模块被停用。
- 实际模块目录不是默认路径。

先执行「环境自检」，确认后再修改「模块目录」。

### GADGET=missing

检查模块目录中是否存在 `libgadget.so` 或 `libgadget32.so`。也可以在「工具与环境」中导入与设备架构匹配的 gadget。

### 推送完成但没有注入日志

依次检查：

1. 目标是否处于启用状态。
2. 包名或进程名是否准确。
3. 编辑后是否执行了「保存并推送」或主界面的「推送并应用」。
4. 目标进程是否已经彻底重启。
5. 当前延时是否尚未结束。
6. 模块是否在 root/Zygisk 环境中实际生效。

### 应用一直停在启动界面

如果使用 `listen` 且启用了 `on_load=wait`，应用会等待 Frida 客户端连接。连接客户端、关闭该选项，或改用 `script` 模式。

### Frida 报无法创建 socket

目标应用没有 `INTERNET` 权限时，`listen` 和 `connect` 可能失败。改用不需要网络 socket 的 `script` 模式。

### 脚本没有执行

检查「ZFM (loader)」和「Frida」日志：

- `ok=false`：查看前面的解密、`Script.load` 或执行错误。
- 解密失败：核对脚本处理方式和密钥。
- 文件不存在：重新选择脚本并推送。
- gadget 架构错误：切换 32 位或 64 位 gadget。
- 不再以自动 Toast 判断是否加载成功；查看脚本自身日志或加密 loader 的 `ZFM` 日志。

### 删除目标后仍然注入

删除只会先修改管理器本机列表。回到主界面再点一次「推送并应用」，设备上的 `config.json` 才会更新。

### 设备上的目标会在推送时丢失

当确认窗口提示存在“本机不管理的目标”时，先取消推送，再使用「从设备导入 → 合并到本机」，确认列表完整后重新推送。

## 13. 建议的排查顺序

遇到问题时按以下顺序处理，通常能快速确定故障位置：

1. 「工具与环境 → 测试 Root」。
2. 「工具与环境 → 环境自检」。
3. 「工具与环境 → 查看 config」。
4. 检查目标启用状态、进程名、延时和 gadget 架构。
5. 主界面执行「推送并应用」。
6. 打开「查看日志 → 全部关键标签」。
7. 对目标执行「强行停止并重启」。
8. 先看 `ZygiskFrida` 是否识别并注入，再看 `Frida` 是否启动，最后看 `ZFM` 是否加载脚本。

这三个阶段分别对应模块、gadget 和脚本 loader。按阶段查看日志，比只观察目标应用是否闪退更容易定位问题。
