# 应用与脚本配置

## 操作流程

1. 打开底部「脚本」，点击加号创建脚本配置。
2. 点击列表项，设置脚本处理方式、密钥以及 Gadget 参数，选择文件并推送。
3. 打开目标应用的编辑页，点击「选择注入脚本」，选择列表中的配置。
4. 点击「保存并推送」，重启目标应用。仅「保存」不会改写设备配置。

可以让多个应用引用同一份脚本配置，也可以为不同应用选择不同脚本。
列表提供重命名和删除；删除时，所有引用该脚本的应用自动切回默认配置并保存，推送并应用后生效。
目标进程包名仅展示和复制，更换应用只能通过「选择」按钮；子配置锁定的目标仍不可更换。
新配置的同名脚本文件分别放在独立目录，不会覆盖彼此。

「默认配置」保留旧版本的全局 Gadget 设置与脚本。未选择独立脚本的旧目标继续使用它。
子配置导入会创建一项独立脚本并绑定到目标；密钥保持隐藏，脚本选择和配置保持锁定。
子配置导出使用该目标绑定的脚本。

## 存储与注入

- 脚本有稳定 ID，名称可修改。每个 ID 对应独立的本地设置和设备脚本目录。
- 应用绑定保存在 `targets.meta.json` 的 `script_id`，不混入模块的配置格式。
- 推送时为使用独立脚本的应用复制所选架构的 Gadget，并在副本旁写入对应配置。
- 模块收到的 `injected_libraries` 指向副本，本机编辑列表保留原库路径。
- 主进程和子进程注入使用不同的副本路径；其他自定义库保持原样。
- 已停用目标不要求脚本就绪。启用目标的脚本缺失、配置禁用或未配置 Gadget 时，推送会报错。
- 已生成的设备文件不会在删除本地条目时自动清理，避免影响仍在运行或尚未重新推送的配置。

此方案兼容原有模块和 Gadget，无需重编译 native 部分，但每个应用的 Gadget 副本会增加存储占用。

## 原生多配置的另一条路线

外部 ZygiskFrida 模块负责选择目标，Gadget 自己负责读取其旁边的 `.config` / `.config.so`。
仅将模块的 `config.json` 拆分为多个文件，不会改变 Gadget 的配置选择。

如果只需要按应用分发脚本，可评估 Gadget 的 `script-directory` 配合每个脚本的进程过滤配置。
如果需要按应用切换完整 Gadget 配置，可在 Gadget 的 `load_config()` 中增加进程名到配置文件的映射，
并在未找到专属配置时回退到原来的配置路径。后一种方式需要自行构建并维护 Gadget。
这些属于上游实现的其他设计方向。本管理器仅使用现有发布产物，不包含或修改这两个 native 读取入口，依赖约定见 [外部依赖说明](upstream_zh.md)。

## 日志

读取线程将日志写入有界缓冲区，界面每 250 ms 批量刷新；显示和待显示文本均有容量上限。
「全部」仅回放最近 300 行；单标签和「全部关键标签」读取系统缓冲区内的匹配日志，避免稀疏日志被系统日志挤出最近 300 行。
暂停时切换标签保持暂停，向上滚动后不会被每批新日志强制拉到底部。
离开页面停止采集；不同采集会话不共用待显示缓冲区。

目标的更多菜单提供独立的「停止应用」和「强行停止并重启」。停止操作检查命令结果和进程是否退出，
不会修改该目标的注入启用状态。启用、停用控制的是后续启动时是否注入，不代表应用当前是否运行。
